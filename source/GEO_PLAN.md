# PX 구매 가이드 GEO 보완 계획서

작성일: 2026-09-23  
대상: `px-monthly-guide-2026`  
범위: Sites 원본(`build.mjs`, `content/`, 생성된 `dist/`)의 콘텐츠·기술 구조 검토. 검색엔진의 실제 수집 상태, Search Console 데이터, AI 답변의 노출·인용 여부는 확인하지 못했다.

## 적용 현황 · 2026-09-23

- 핵심 5개 가이드에 직접 답변, 적용 범위, 참고 출처 또는 자체 계산 근거를 본문 앞뒤에 표시했다. 수정일을 실제 작업 날짜로 기록하고, 보이는 내용과 같은 `Article` 데이터를 붙였다. 출처 링크는 특정 PX 할인·재고를 입증하는 자료로 쓰지 않았다.
- 보조 가이드 30개의 반복 문단 300개를 제거하고, URL별 주제에 맞춘 두 개의 독립적인 판단 문단으로 교체했다. 30개 URL은 **개선 후 유지**로 일단 판단했다. 검색 유입·외부 링크 데이터를 확보하기 전에는 통합·리디렉션·색인 제외를 결정하지 않는다.
- 글 분량 3,000자 강제와 임의의 2026년 4~6월 날짜를 제거했다. 원고를 실제 수정한 글만 2026-09-23 수정일을 표시하고 사이트맵 `lastmod`에 반영한다. 예전 게시일과 외부 자료 확인일은 알 수 없어 기입하지 않았다.
- 제품 소개 12개의 분량 채우기용 반복 문단을 걷어 내고, 상품 식별 정보와 PX 판매·가격 미확인 범위를 분리했다. 소개 페이지에 출처, 수정, 오류 제보 원칙을 밝혔다. 확인되지 않은 월별 할인 0건은 그대로 유지한다.
- **남은 운영 작업:** Search Console/Bing 소유 확인과 색인 진단, 질문별 AI 인용 관측, 제품 이미지 사용 허가와 개별 상품 링크의 정기 검수, 할인 자료의 실제 확인일 기록. 이 작업에는 계정 권한과 후속 현장·자료 확인이 필요하다. 구조화 데이터와 문서 개선이 인용을 보장하지는 않는다.

## 판단 요약

**우선순위는 페이지 수 확대가 아니라 검증 가능한 답변의 밀도와 출처·날짜의 정직성이다.** Google은 AI Overviews·AI Mode에 별도 GEO 마크업이나 AI 전용 파일을 요구하지 않는다. 검색 색인과 스니펫 자격, 사람에게 유용한 원문, 읽기 쉬운 텍스트, 내부 링크, 화면 내용과 일치하는 구조화 데이터가 기본이다.[1]

| 확인한 상태 | GEO에 미치는 영향 | 권고 |
|---|---|---|
| `robots.txt`, XML 사이트맵, 페이지별 canonical 및 서버에서 완성된 HTML이 있다. | 기본 발견 가능성은 갖췄다. 실제 수집·색인은 별도 확인이 필요하다. | 유지하고 Search Console로 대표 URL의 색인·스니펫 상태 확인. |
| 가이드 39개 중 30개는 `build.mjs`에서 생성된다. 이 30개는 각기 10단계의 같은 문단 틀에 주제명만 넣는다. 기존 9개에도 `expanded.json`으로 분량을 보강한다. | 질문별 고유한 답, 근거, 예시가 부족해 독자와 인용자가 차이를 파악하기 어렵다. | 품질을 확인한 핵심 문서부터 재작성하고 중복·빈약한 글은 통합 또는 비공개 검토. 글자 수 3,000자 빌드 기준을 품질 기준으로 쓰지 않기. |
| 가이드 날짜는 게시 이력에서 읽지 않고 빌드 시 2026년 4월·6월의 일련 날짜로 채워진다. 본문에는 고정된 `2026.09.22 편집` 문구를 쓴 뒤 다른 날짜로 다시 치환한다. 제품 날짜도 일련 날짜다. | 독자가 실제 확인일과 수정일을 구분할 수 없다. 검색 시스템의 날짜 해석도 혼란스러울 수 있다.[2] | 검증된 `datePublished`, `dateModified`, `reviewedAt`만 콘텐츠 데이터에 저장하고 화면·사이트맵·구조화 데이터에서 일치시키기. 이력이 없으면 날짜를 추정하지 않기. |
| 2026년 9월 할인 항목은 0개이며, 미확인 행사를 표시하지 않는다. | 허위 최신성 방지에 도움이 된다. 다만 방문자는 언제 다시 확인했는지 알기 어렵다. | 마지막 점검 시점과 확인 대상 출처를 실제 확인 후 표시. 출처가 없을 때는 계속 빈 상태를 유지. |
| 독립 사이트·광고 미설치·문의 경로가 소개 페이지에 있으나, 개별 가이드의 사실 주장과 1차 출처 연결은 제한적이다. | 답변의 출처와 책임 주체를 해당 문서에서 추적하기 어렵다. | 글마다 자료명, 발행 주체, URL, 확인일, 적용 범위, 자체 판단을 짧은 ‘근거와 확인 범위’로 공개. 운영자 이름·전문성은 실제 확인 가능한 정보만 표기. |
| 가이드와 제품 상세에는 JSON-LD가 없다. 제품 페이지는 실제 PX 가격·재고를 확인하지 않는다. | 내용 이해를 돕는 정합성 신호가 부족하다. | 사실을 검증한 문서에만 `Article`/`WebPage`를 검토. 미확인 PX 판매 가격에 `Product`/`Offer`를 붙이지 않기. 구조화 데이터는 인용 보장이 아니다.[1][3] |

## 실행 순서

### P0 — 첫 1~2주: 신뢰와 콘텐츠 정리

1. **날짜와 확인 기록 정정**: 임의로 생성한 날짜·고정 ‘편집’ 문구를 제거한다. 원본에 `publishedAt`, `modifiedAt`, `reviewedAt`과 검증 출처를 분리한다. 실제 기록이 없는 글은 ‘최종 확인일 미기재’로 두고, 이후 확인 작업을 거쳐 기입한다. 월별 페이지에는 월 표시와 별개로 자료의 실제 점검일을 둔다.
2. **핵심 5개 글부터 재작성**: `/guides/px-shopping-checklist/`, `/guides/compare-unit-prices/`, `/guides/monthly-deal-guide/`, `/guides/px-skincare-starter/`, `/guides/px-food-shopping-list/`. 각 글 첫 화면에 질문에 대한 2~3문장 직접 답변, 적용 조건, 예외를 둔다. 본문은 독자적인 비교표·실제 계산 예시·근거 링크 중심으로 바꾼다. 가상의 가격은 예시라고 명시한다.
3. **30개 생성형 글의 발행 판단**: URL별 고유 정보·검증 가능한 근거·유용한 사례가 있는지 표로 심사한다. 부족한 글은 좋은 글로 통합하고 리디렉션하거나 색인 제외를 검토한다. 일괄 삭제 전에 유입·링크 데이터를 확인한다. 신규 글은 최소 글자 수보다 질문 해결·근거 검증·편집 승인 조건을 통과해야 게시한다.[4]
4. **출처와 책임 범위**: 공식 PX 행사 자료가 없는 월별 할인은 계속 공란으로 둔다. 브랜드 제품 설명은 브랜드의 공식 페이지와 독립적 구매 조언을 문장 단위로 구분한다. 이미지의 ‘공식’ 표기와 사용 허가도 항목별 재검토한다.

### P1 — 3~4주: 인용 가능한 문서 구조와 기술 정합성

1. **문서별 사실 카드**: ‘무엇을 확인했나 / 언제 / 어디에서 / 어디까지 적용되나’를 짧게 표기한다. 예: `가격은 100ml당 3,000원(가상 예시), 단위가격 = 실제 결제액 ÷ 전체 용량 × 100`처럼 계산 근거를 본문 텍스트와 표로 같이 제공한다.
2. **구조화 데이터는 본문과 일치할 때만**: 핵심 가이드에 `Article` 또는 `WebPage`의 제목·설명·실제 날짜·실제 운영 주체·canonical URL을 연결하고 검증 도구로 확인한다. 제품 사진만으로 현재 판매 `Offer`를 만들지 않는다.[3]
3. **발견과 이동**: 주제 허브에서 핵심 질문별 대표 글로 연결하고, 비슷한 글 사이 중복된 목차를 줄인다. 사이트맵 `lastmod`는 확인된 변경 날짜가 있을 때만 넣는다. HTML에서 주요 답변·표·출처가 자바스크립트 없이 읽히는지 유지한다.[1]
4. **소개·교정 절차**: 편집 기준, 자료 검증 방법, 오류 신고 및 수정 이력 원칙을 `/about/`에서 더 구체적으로 밝힌다. 공개 가능한 운영자 정보만 쓰고 확인되지 않은 전문 자격은 쓰지 않는다.

### P2 — 30~60일: 관측과 반복

1. Search Console에 사이트맵을 제출하고 대표 URL의 수집·색인·스니펫 상태, 검색어별 노출·클릭을 기준선으로 저장한다. Bing Webmaster Tools도 연결할 수 있으면 같은 URL 집합을 확인한다. 연결은 소유자 계정 권한이 필요하다.
2. 실제 독자 질문 15~20개를 정해 월 1회 동일 조건으로 검색·AI 답변을 관찰한다. 사이트의 직접 인용·링크·오인용을 URL과 캡처 시각로 기록한다. 개인화와 시간에 따라 결과가 바뀌므로 인용률을 보장 지표로 해석하지 않는다.
3. 월별 할인은 `출처 확보 → 대상 매장·기간·규격 검증 → 확인일 기입 → 게시 → 기간 종료 후 보관` 절차를 운영한다. 자료를 구하지 못한 달은 “확인된 품목 없음” 상태를 유지한다.

## 범위와 유의점

이 계획은 원본 및 빌드 산출물 감사를 바탕으로 했다. 실제 검색 순위, AI 답변 인용, 이미지 원본 권리, 링크 대상의 현재 내용, 방문자 로그는 조사 범위 밖이다. 우선순위는 이 데이터를 얻은 뒤 조정한다. `llms.txt`, 대량 FAQ 마크업, AI 크롤러 전체 허용 같은 조치를 인용을 보장하는 필수 항목으로 취급하지 않는다.[1]
