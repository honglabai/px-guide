# 쿠팡 가격 순환 갱신 설계

## 목적과 성공 기준

PX 구매 가이드의 쿠팡 비교가를 사용자의 Mac이 켜져 있을 때 Ego Lite 브라우저로 주기적으로 확인한다. 상품과 옵션이 확실히 일치하고 가격 변동이 검증된 경우에만 현재가를 바꾼다. 나머지는 출처와 이유를 기록해 운영자가 검토한다. PX 가격과 월별 할인 기록은 이 기능이 수정하지 않는다.

사용자가 승인한 실행 범위는 한국 시간 하루 5회, 실행당 최대 20개 상품이다. 실행 시각은 07:00, 10:00, 13:00, 16:00, 20:00으로 둔다. Mac이 꺼져 있거나 자동 작업을 실행할 수 없는 동안에는 갱신되지 않는다. 다음 실행에서 미처리 상품을 다시 선택하며, 놓친 횟수만큼 한꺼번에 20개를 초과해 처리하지 않는다. 전체 2,278개를 한 차례 확인하는 데에는 우선순위가 균등하더라도 최소 23일이 걸린다.

## 현재 구조와 변경 범위

- `content/products.json`에 2,278개 상품이 있다. `officialPrice`와 `priceCheckedAt`은 빌드 시 정적 HTML과 `favorites-data.json`으로 복사된다. 기존 D1에는 `daily_visits`만 있으며 가격 갱신 기능이 없다.
- 기존 `officialPrice`는 과거 비교 기록으로 보존한다. `priceSeller`가 쿠팡이라고 적혀 있어도 쿠팡 직접 가격 출처 URL은 거의 없다. `officialPriceUrl` 또는 `productUrl`의 호스트가 `coupang.com` 계열일 때만 기존 쿠팡 링크로 사용한다. 다른 판매처 URL을 쿠팡 출처로 취급하지 않는다.
- 새 가격은 D1에서 조회하며 정적 가격 파일을 매 실행마다 수정하거나 사이트를 재배포하지 않는다. 브라우저에 보여 주는 현재가는 검증된 D1 값만 사용한다. 검증값이 없는 상품에는 기존 비교가를 확인일이 붙은 과거 기록으로 표시한다.
- 찜과 장바구니는 현재 방문자 브라우저의 로컬 저장소에만 있다. 갱신 우선순위용 인기도는 상품별 익명 합계만 별도 수집한다. 개별 방문자의 찜 목록이나 장바구니 내용을 서버로 보내지 않는다.

## 구성 요소와 데이터 흐름

1. **상품 색인과 큐.** 빌드가 상품의 `slug`, 이름, 브랜드, 규격, 기존 쿠팡 링크를 정적 색인으로 내보낸다. D1의 `price_update_queue`는 상품별 최근 실행, 다음 실행, 시도 횟수, 우선순위, 상태를 보관한다. 초기 등록은 게시 후 소유자 전용 도구로 분할 수행하며, 중복 등록은 안전하게 무시한다.
2. **Mac의 정기 실행.** 현재 로컬 Codex 작업에 연결된 자동 작업이 위 시각에 실행된다. 소유자 전용 Site MCP 도구로 최대 20개의 처리 대상과 상품 색인을 받고, Ego Lite에서 한 작업 공간과 재사용 가능한 페이지를 열어 순서대로 확인한다. 각 대상의 이름·브랜드·규격으로 쿠팡을 검색하고, 후보 상세 페이지에서 상품·옵션·가격을 다시 읽는다. 기존 쿠팡 URL이 있으면 검색 후보를 대조하는 근거로 사용한다. 로그인, CAPTCHA, 접근 차단을 우회하지 않는다. 브라우저 확인 결과는 Site MCP 도구에 제출한다.
3. **판정 및 저장.** Site 서버는 브라우저 결과를 그대로 신뢰하지 않는다. URL 호스트, 금액, 상품명, 규격, 수량, 관찰 시각을 검증하고 점수를 다시 계산한다. 모든 시도는 `price_history`에 남기고 승인된 값만 `coupang_price_current`에 반영한다. 재검증이나 관리자 판단이 필요하면 `REVIEW`에 넣는다.
4. **공개 화면.** 공개 읽기 API는 승인된 현재가와 확인일만 반환한다. 상품 카드에는 `쿠팡 확인 MM.DD`를 작게 표시한다. 상세에는 쿠팡 일반 표시가, PX가와의 차액·절감률, 확인일, 배송비 별도 여부와 원본 상품 링크를 표시한다. 검색 목록, 찜, 장바구니가 같은 승인값을 사용한다. 30일 넘게 재확인하지 못한 값에는 `재확인 필요`를 붙인다. 오래된 정적 비교가는 현재가로 표현하지 않는다.
5. **관리 화면.** `/admin/coupang-prices/`에서 대기·재검증·차단·검토·승인 결과, 원본 URL, 상품/옵션 비교, 가격 이력을 확인하고 후보를 승인·거부·재시도할 수 있다. 공개 사이트의 이 경로와 쓰기 도구는 ChatGPT 로그인 후 소유자임을 서버에서 확인한다.

## 데이터 모델

- `coupang_price_current`: `product_slug` 기본키, 쿠팡 `product_id`/`item_id`/`vendor_item_id`, 정규화한 상품명·규격·수량, 표시가, 배송비, 판매자/가격 조건, 원본 URL, 매칭 점수, 확인일, 마지막 이력 ID. PX가는 넣지 않는다.
- `price_history`: 변경 불가능한 시도·검토 결정별 행. 상품, 시도/관찰 시각, 출처 URL, 관찰한 제목·옵션·가격·배송비, 매칭 점수와 규칙별 결과, 가격 변동률, 결과 상태, 차단/실패 이유를 담는다. 승인·거부는 원래 관찰 행을 바꾸지 않고 검토자와 검토 시각을 포함한 새 결정 행으로 남긴다. 가격을 찾지 못한 시도도 기록한다.
- `price_update_queue`: 상품별 한 행. `status`는 `PENDING`, `RUNNING`, `REVIEW`, `BLOCKED`, `RETRY`, `DONE` 중 하나이며 실행 잠금 만료 시각과 다음 시도 시각을 둔다. `RUNNING`의 잠금이 만료되면 다시 선택할 수 있어 중단된 실행이 큐를 영구 점유하지 않는다.
- `product_interest_daily`: 날짜와 상품별 익명 찜·장바구니 추가 횟수의 합계. 개인 식별자, 개별 목록, 원문 IP는 저장하지 않는다. 클라이언트는 같은 날짜·상품·행동의 중복 전송을 줄이고 서버는 입력량을 제한한다. 개인정보 안내에 이 집계 목적을 적는다.

상품 정보의 기준은 계속 `content/products.json`이다. D1의 가격 행은 `product_slug`로 연결한다. 기존 `officialPrice`를 새 현재가 테이블로 일괄 복사하지 않는다.

## 검색과 판정 규칙

- 매번 상품 이름에 브랜드·규격을 더해 검색한다. 기존 쿠팡 상세 URL은 `itemId`와 `vendorItemId`를 포함한 선택 옵션까지 보존해 후보 대조에 사용한다. 검색 결과에서는 광고 여부와 무관하게 후보의 제목, 규격, 수량, 선택 옵션, 판매가, 배송비, 원본 링크를 읽는다. 검색 카드만으로 자동 승인하지 않고 후보 상세에서 다시 확인한다.
- 상품 일치 점수는 브랜드 15점, 제품명 35점, 용량 20점, 구성 수량 20점, 옵션 10점이다. 용량 또는 구성 수량이 명시적으로 다르면 점수와 관계없이 자동 반영을 금지한다. 필수 정보가 읽히지 않으면 추측해 채우지 않는다.
- 일치 점수 95점 이상이면 가격 판정으로 진행한다. 85~94점은 `REVIEW`, 85점 미만은 미반영이다. 같은 상품의 여러 판매자가 보이면 상품 표시가를 기준으로 후보를 비교하되 배송비와 판매자 조건을 함께 기록한다. 쿠폰·와우 전용·로그인 조건 가격은 일반 표시가로 자동 반영하지 않는다. 동일 옵션에 서로 크게 다른 가격이 남으면 `REVIEW`로 보낸다.
- 마지막 승인 현재가 대비 절대 변동률 20% 이하는 자동 반영한다. 20% 초과~40% 이하는 같은 옵션의 상세를 한 번 더 확인해 일치할 때 반영하고, 재검증이 불완전하면 `REVIEW`로 보낸다. 40% 초과는 `REVIEW`다. 처음 확인한 상품은 기존 정적 가격과 비교해 이상치 판정하되, 기존 가격을 검증된 현재가로 간주하지 않는다.
- `BLOCKED`, `CAPTCHA`, `LOGIN_REQUIRED`를 감지하면 해당 시도와 실행 전체를 중단하고 이유를 기록한다. 자동 재시도는 지수형 대기 간격을 적용하며, 동일 세션에서 새 브라우저나 계정으로 회피하지 않는다. 네트워크 오류, 페이지 구조 변경, 가격 없음은 각각 별도 실패 상태로 기록한다.

## 우선순위와 실행 한도

큐는 진행 중인 월별 할인 상품, 최근 익명 찜·장바구니 합계, 과거 가격 변동성, 마지막 확인 후 경과 시간 순으로 점수를 만든다. 일정 기간 확인하지 못한 상품에 최소 우선순위를 부여해 인기 상품만 반복 선택되지 않게 한다. 검토 대기 상품은 운영자 처리 전 자동 현재가 변경을 하지 않는다. 한 실행은 최대 20개를 예약하고, 요청 사이에 간격을 두며, 차단 신호가 있으면 즉시 멈춘다.

## 인증과 접근 제어

사이트는 공개 상태를 유지한다. Site MCP의 `/mcp`는 Sites가 요청자를 인증한 뒤 전달하며, 서버는 쓰기 도구마다 확인된 로그인 이메일이 사이트 소유자 허용 목록에 있는지 다시 검사한다. 관리 API도 동일하게 검사한다. 허용 목록은 사이트 런타임 설정에만 두고 소스·브라우저 코드·자동 작업 프롬프트에 비밀이나 토큰을 넣지 않는다. 공개 가격 API는 읽기만 허용하며 사용자 제출 가격을 받지 않는다.

## 구현·검증 순서

1. 새 D1 스키마와 마이그레이션을 추가하고 로컬에서 적용한다. 정적 상품 색인과 가격 판정 함수를 분리한다.
2. 소유자 전용 Site MCP 큐/기록/검토 도구, 공개 현재가 API, 관리 화면을 만든다. 익명 인기 합계는 필요한 최소 이벤트만 받는다.
3. 기존 페이지에 승인 현재가 조회와 확인일 표시를 연결한다. 정적 과거 가격의 문구와 날짜를 바로잡는다.
4. Ego Lite 수집기를 만들고, 기존 링크가 있는 상품 1건과 링크 없이 검색하는 상품 1건으로 드라이런한다. 두 경우 모두 이름으로 검색한다. 400ml 낱개와 6개 묶음처럼 수량이 다른 후보, 배송비가 다른 동일 옵션, 차단 페이지를 검증한다.
5. 기존 테스트와 새 판정·인증·큐 테스트, 사이트 빌드, 실제 사이트의 읽기·쓰기 결과를 확인한 뒤 배포한다. Site MCP 연결과 저장된 현재가 읽기를 확인한 다음에만 Mac의 정기 자동 작업을 켠다. 예약 실행을 기다리는 대신 같은 실행 경로로 1회 수동 검증한다.

## 한계와 운영 원칙

쿠팡 공개 페이지의 구조, 가격, 접근 조건은 바뀔 수 있다. Ego Lite가 읽지 못한 값은 갱신하지 않는다. 하루 최대 100개이므로 전체 상품을 매일 최신 상태로 만들 수 없다. Mac이 잠자거나 꺼진 동안에는 자동 작업이 실행되지 않는다. 사용자의 기존 가격 자료와 월별 할인 기록은 보존하며, 새 현재가가 없을 때 확인되지 않은 쿠팡 가격을 최신가로 단정하지 않는다.
