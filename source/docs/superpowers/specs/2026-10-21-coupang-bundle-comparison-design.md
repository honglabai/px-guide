# 검증된 묶음가의 PX 판매 단위 환산 설계

## 결정과 범위

사용자는 기존 자료에서 `comparisonKind: "sameBundle"`로 확인된 묶음에 한해 쿠팡의 묶음 표시가를 PX 판매 단위 가격으로 환산하는 방식을 선택했다. `comparisonQuantity`는 온라인 묶음에 포함된 **PX 판매 단위의 수**다. PX 판매 단위 자체에 들어 있는 병·개수와 구별한다. 기존 가격 기록의 출처가 불확실한 `unverifiedBundle`, `differentBundle`, 수량 누락 항목은 자동 현재가 대상이 아니다.

예: 로투스 125g은 PX 판매 단위가 125g 한 개이고 `comparisonQuantity=20`이므로 온라인 20개 표시가를 20으로 나눈다. 제주삼다수 그린 500ml×20병은 PX 판매 단위가 이미 20병이고 `comparisonQuantity=1`이므로 온라인 20병 묶음 표시가를 그대로 비교한다. 던킨 400ml의 `comparisonQuantity=24`는 24병 온라인 표시가를 24로 나눈다.

## 승인 조건

원본 카탈로그의 `comparisonQuantity`는 검색 대상에 대한 근거일 뿐, 쿠팡 화면에서 실제 묶음을 확인했다는 증거가 아니다. Ego Lite 검색 카드와 상세 페이지의 선택 옵션 제목, 규격, 묶음 수량, 상품·옵션·판매자 ID를 읽고 서버가 같은 조건을 재검증한다. 후보가 여러 개면 가격을 선택하지 않고 검토로 보낸다. 기존 쿠팡 링크는 일치 여부의 힌트이며, URL만으로 승인하지 않는다.

- `sameBundle`이며 양의 안전한 정수 `comparisonQuantity=q`가 있는 상품만 자동 대상이다.
- PX 판매 단위의 내부 수량이 이름·규격에 명시되고 `q>1`인 중첩 묶음은 첫 범위에서 자동 승인하지 않는다. 온라인 화면에 내부 수량과 바깥 수량이 별도로 드러나기 전에는 추측할 수 없다.
- 내부 수량이 없는 PX 판매 단위는 선택 상품 제목에 `q개/팩/병` 등의 수량이 명시되어야 한다. `q=1`도 온라인의 1개 증거가 필요하다. 내부 수량이 명시된 PX 묶음에서 `q=1`이면 그 내부 수량과 규격이 선택 상품에 일치해야 한다.
- 선택 옵션이나 검색 카드에 서로 모순되는 수량·규격이 있거나 수량이 보이지 않으면 자동 현재가로 승인하지 않는다. `sameBundle` 분류만으로 누락 수량을 1로 채우지 않는다.
- 일반 표시가와 쿠폰·와우·카드 조건가를 혼동하지 않는다. 선택된 판매가와 배송비를 별도 기록한다. 서로 다른 판매자나 가격이 같은 상품·옵션에 남으면 검토한다.
- 기존 가격과 비교할 때도 같은 PX 판매 단위 기준을 쓴다. 첫 관찰의 기준은 `officialPrice * q`인 온라인 묶음 총액이고, 이후에는 같은 `q`와 판매 단위의 마지막 승인 총액이다. 20%·40% 규칙과 재확인은 기존 설계를 따른다. 판매 단위나 `q`가 바뀌면 기존 현재가와 조용히 비교하지 않고 검토한다.

## 저장과 표시

관찰 이력과 현재가에는 쿠팡이 실제 표시한 **묶음 총액** `displayedPrice`, 배송비, 검증된 `comparisonQuantity`, 선택 상품·판매자 식별자, 제목, 원본 URL, 시각과 판정 이유를 보존한다. 단위 가격은 `displayedPrice / comparisonQuantity`로 계산하며 총액을 단위 가격으로 덮어쓰지 않는다. 가격 비교와 찜·장바구니 계산은 이 단위 가격을 사용한다. 원화 표시 반올림은 출력에서만 하며 변동률과 차액 판정은 총액·수량의 정수 산술을 사용한다.

공개 화면은 `쿠팡 묶음 표시가 25,950원 / 20개`, `PX 판매 단위당 약 1,298원`, 확인일과 배송비 별도 여부를 함께 보여 준다. 묶음 수량·배송비가 실제 결제 금액에 영향을 주므로 배송비를 제외한 차액은 구매 총절약액처럼 표현하지 않는다. 검증 현재가가 없으면 기존 정적 비교가는 확인일이 붙은 과거 기록으로 남는다. 관리자 화면은 총액·환산 분모·선택 옵션·판매자·배송비·판정 근거를 함께 보여 준다.

## 운영 한계

브라우저 접근 차단·로그인·CAPTCHA에는 기존 중단 규칙을 지킨다. 페이지 구조가 바뀌거나 묶음 증거를 읽지 못하면 현재가는 갱신하지 않는다. 하루 5회, 회당 최대 20개, Mac이 깨어 있을 때만 실행한다. PX가와 월별 할인 기록은 변경하지 않는다.
