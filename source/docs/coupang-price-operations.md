# Coupang observation operations

Claim up to 20 products with the owner-only `get_price_batch` MCP tool and save its `items` locally. Run:

```sh
node scripts/collect-coupang-prices.mjs /absolute/path/batch.json > observations.json
```

The CLI launches `ego-browser nodejs`, creates exactly one TaskSpace, prints its ID to stderr, and reuses page `p1` for searches and details. It accepts only a local batch file, has no Site credential parameter, and makes no Site writes. Submit the resulting JSON through the authenticated `submit_price_observations` MCP tool. Never put credentials in batch files. Mac must remain awake, signed in, connected, and able to run Ego Lite; a sleeping Mac cannot perform a scheduled collection. Every claimed item must include the server-derived target `quantity` and positive `comparisonQuantity`. `referencePrice` and `previousPrice`, when present, are raw online bundle totals; the collector checks only their shape and never converts or trusts a unit price.

Each navigation pauses 1.5 seconds, waits for loaded observable content, and has a 20 second overall deadline. A timed-out remote operation is never followed by another navigation. The CLI streams startup, TaskSpace ID and navigation diagnostics to stderr; local import follows ID output. Allocation and import each have a 30 second deadline. The batch deadline is 120 seconds plus 3 × 21.5 seconds per item (23.5 minutes for 20 items), below the queue’s 30 minute lease when started promptly. No timeout automatically retries or creates a replacement space. Search includes name, brand, specification, quantity and option unless a curated `comparisonSearchQuery` is present. Missing quantity is not inferred. A unique candidate must score at least 95 with no hard mismatch. IDs and URL must remain stable on detail. Conflicting sellers, missing price, changed pages and ambiguous prices fail closed. Shipping is separate from displayed price. The parser intentionally rejects pages containing several unexplained prices; markup changes may require parser maintenance. Existing links constrain any product/item/vendor IDs they contain; a conflicting search result produces IDENTITY_CHANGED. Every item is searched anew.

## Verified name aliases and PX sale units

`content/products.json` may define `comparisonAliases` as an explicit list of names verified for that product and `comparisonSearchQuery` as a concise search phrase. The build includes these fields in `price-catalog.json`; the owner-only batch carries them to the collector. The original catalog name stays valid when aliases are added, but it still needs the brand to be visible in the title. Brand visibility is checked with the same normalized text as matching, so spacing differences do not create an empty brand in a verified observation. An explicitly listed alias alone can establish both name and brand identity. Each path checks an exact normalized name core after removing visible size and count text, so a different flavor or label variant is not accepted by substring alone. The collector and server both match the card and selected detail title against the catalog names; the server does not accept an observation's self-reported brand as alias evidence. Card and detail must resolve to the same name core. The visible size, quantity count and unit, option, IDs, seller, ordinary price and card/detail price agreement remain separate gates. Add aliases only after confirming product identity; an unknown product has no alias rule. Changing the aliases changes the comparison basis, so an already accepted current price requires review before replacement.

For every `sameBundle` product, `comparisonQuantity` is the number of PX sale units in the online offer. The stored `displayedPrice` is always the raw Coupang total and the public comparison price is `displayedPrice / comparisonQuantity`. Lotus Biscoff 125g has one PX packet at 820원 and `comparisonQuantity: 20`; a verified 20-packet Coupang total is divided by 20 before comparing. Samdasu Green 500ml has a PX 20-bottle package at 8,190원 and `comparisonQuantity: 1`; a verified 20-bottle Coupang total is compared as is. Its curated aliases are `제주삼다수 그린`, `제주삼다수`, and `삼다수`; all still require visible 500ml and 20병. Other products can use the same metadata only when identity and bundle equivalence are documented.

A >20% and <=40% change against `previousPrice` reads the exact detail URL again. Only an identical title, IDs, URL and price creates `recheck` with a later timestamp. Server acceptance requires this evidence; a `reverified` boolean alone has no effect. If no prior current price exists, the claimed `referencePrice` supplies the baseline; the server independently verifies against its catalog reference.

CAPTCHA, login requirements and access blocks stop the entire run immediately. Never solve, bypass, relaunch into another TaskSpace or retry a blocked page in the run. Successful runs call `finish({keep:[]})` once. Blocked/error spaces stay available for inspection. User takeover is propagated as an error. After an interrupted run, inspect the printed TaskSpace rather than blindly rerunning the CLI. Unvisited claims become available when their 30 minute lease expires.

Failure submissions contain `observationId`, `slug`, `failure`, `sourceUrl`, `observedAt`, and no price. History preserves immutable attempts; current price stays unchanged. Block/login/CAPTCHA and transient failures schedule retries after 5 minutes times 2^(claim attempts - 1), capped at 24 hours. Identity ambiguity goes to owner review. A failure without a price cannot be accepted manually. Failure replay preserves its original record and retry timestamp.

Live checks must be dry runs until observations are reviewed. Browser bootstrap errors need authorized access outside the agent sandbox; do not substitute another browser or direct scraping. Collection is conservative and may yield no verified prices when Coupang is blocked or its page layout changes.

## Selected-offer extraction and verification limits

Detail extraction supports one visible semantic Product/Offer or the observed Coupang selected-offer layout described below. Both require one selected title, visible specification and count, ordinary price, shipping, and seller. It scopes shipping and seller to that Offer and rejects unselected alternatives, multiple sellers/prices, and coupon/Wow/member/card/subscription conditions. Conditional text within the Product also prevents automatic collection. Missing or ambiguous semantic markup returns PAGE_CHANGED rather than extracting arbitrary prices from the page body. The standard semantic fallback remains supported. The Coupang adapter uses DOM fragments captured by the controller in approved Ego Lite TaskSpace 2. No quantity is inferred when the catalog has none.

Success observations preserve the selected detail's raw `displayedPrice`, shipping fee, seller, three IDs, visible title/specification/count, `priceCondition: "일반가"`, timestamp, and a separate `searchCard` with its own visible title/specification/count, price, shipping, and IDs. The collector requires both card and selected detail to match the target count and product. It rejects a card/detail price or shipping disagreement, and a card seller disagreement when a seller is visible on the card. The surrounding option menu cannot establish the selected count. Multiple matching cards or conflicting offers become `AMBIGUOUS_MATCH`; the collector never chooses the cheapest seller. A 20–40% raw bundle change rechecks the same selected detail and retains the second timestamp.

The selected Offer must have exactly one nonempty visible semantic seller; absent, empty or multiple sellers produce PAGE_CHANGED. Conditional-price detection normalizes whitespace and covers card, Wow, membership and subscription wording, including separated words such as `카드 즉시할인` and `와 우 회원`. Search readiness requires the requested URL/query, a visible matching query input and result cards (or an explicit empty-result status). Detail readiness requires the requested product/option URL and visible Product/Offer name and price regions; a generic heading or unrelated product link is insufficient. These checks remain conservative pending live DOM compatibility verification.

## Observed Coupang adapter and existing-space validation

The 2026-10-21 DOM evidence uses search-card class prefixes `ProductUnit_productNameV2__` and `PriceArea_priceArea__`. Search strips visible `del`/line-through prices and per-unit parentheticals while keeping feePrice shipping badges separate. Hidden duplicate query inputs are ignored. Multiple exact cards (including Lotus 1260 + 3000 shipping versus another seller at 5200) remain AMBIGUOUS_MATCH; no cheapest-seller choice is made.

The 2026-10-22 dry run in TaskSpace 3 returned `PAGE_CHANGED` for Lotus after opening detail and `NO_EXACT_MATCH` for Samdasu and Dunkin at search. Collector stderr prints up to three `search-card` rejection samples per item, plus a `search-summary` with fixed-code counts across every examined card, a best rejected match score and reason, and an omitted-sample count. A `detail` code explains rejected selected offers or card/detail mismatches. The detail price diagnosis uses the same ordinary-price line filter as acceptance, so shipping, discounts and repeated identical ordinary prices do not falsely appear as ambiguous prices. Codes distinguish missing title, specification, count, IDs, seller, shipping, conditional or ambiguous prices, and low or conflicting match scores. Diagnostics use item position and fixed codes; they omit page text, card titles, full URLs, cookies and tokens. The JSON observation fields and acceptance rules are unchanged. A subsequent authorized live run is needed to identify the exact current Coupang markup behind these failures; the prior run did not retain raw DOM evidence for them.

For the observed detail layout, `SELLER_LINK_MISSING`, `SELLER_LINK_AMBIGUOUS`, `SELLER_NAME_UNVERIFIED`, `SELLER_ID_UNVERIFIED`, and `SELLER_ID_MISMATCH` distinguish selected-seller evidence failures. `PRICE_REGION_UNVERIFIED`, `PRICE_REGION_AMBIGUOUS`, and `SHIPPING_REGION_AMBIGUOUS` identify structural price/shipping failures. These are diagnostic codes only; the corresponding observation still fails as `PAGE_CHANGED`.

Detail requires unique `h1.product-title`, `.price-container` and `.seller-info`. It reads `.price-layout-container.price-layout-normal` and the nested `.price-shipping-fee-info-container`; surrounding option-list totals are excluded. Seller identity comes from the unique `shop.coupang.com/vid/` link whose `viid` equals the selected vendor item ID, excluding its `판매자 상품 보러가기` label. The `다른 판매자 보기(12)` control is not a second selected seller. Coupon-bearing Dunkin pricing and missing seller evidence fail closed. Source URLs retain product/item/vendor identity and discard search tracking parameters.

To validate within an already authorized active TaskSpace:

```sh
node scripts/collect-coupang-prices.mjs /absolute/path/batch.json --task-space-id 2 > observations.json
```

Resume mode calls only `taskSpace(2)`, never allocates a fallback, and does not claim a user-owned/inactive space. Normal scheduled invocation still allocates exactly one space per run. Successful completion calls finish and closes the resumed space too; blocked/error runs retain it. No Site credential is accepted and no Site write is made. Do not rerun a closed/missing space automatically.

Ego Lite sends runtime console.log output on stderr in the observed desktop configuration; the CLI now recognizes the whole-line observation envelope on either stdout or stderr, buffers each channel separately with UTF-8 decoding, and keeps result payloads out of diagnostics. `[error] collector: ...` remains diagnostic text. Duplicate result envelopes are rejected rather than silently replacing output. Selected vendor IDs must both be nonempty and equal. Detail readiness waits for the selected seller link (or a visible conditional terminal offer), bounded by existing deadlines. Canonically identical search links collapse only when title/price/shipping/condition agree; conflicting duplicates enter review. The approved TaskSpace 2 has finished, so the 2026-10-21 bundle update was verified against its captured DOM fixture and local tests only. A new live collection requires the next authorized scheduled run; no replacement TaskSpace was created for this change.
