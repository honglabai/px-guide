# PX 구매 가이드 운영

이 사이트는 PX 운영기관과 무관한 독립 정보 사이트입니다. 9월 할인 기록과 10월 첨부 자료에서 식별한 품목을 월별 게시물로 보관합니다.

## 월별 할인 갱신

월별 게시물은 `content/monthly-archive/YYYY-MM.json`에 각각 저장합니다. 빌드 시 모든 기록의 고정 주소 `/monthly/YYYY-MM/`와 메뉴 하단 게시물 목록이 생성됩니다. 과거 월 파일은 새 월 게시 때도 그대로 유지합니다.

1. 새 월의 자료를 확인해 별도 JSON 파일로 저장합니다. `month`, `sourceLabel`, `sourceStatus`, `items`를 입력합니다.
2. 품목마다 `name`, `category`, `regularPrice`, `salePrice`, `description`, `period`, `stores`, `sourcePublishedAt`, `sourceLabel`, `productSlug`를 기록합니다. 판독되지 않은 가격은 `null`로 두고 `priceStatus`에 이유를 기록합니다. 출처 게시일은 확인하지 못하면 추정하지 않습니다.
3. 최신 월 파일을 `content/monthly.json`에도 복사합니다. 홈과 `/monthly/`에는 이 월이 표시됩니다. 과거 월의 가격을 최신 행사 가격으로 복사하지 않습니다.
4. 제품 소개는 `content/products.json`의 기존 상품명·규격을 대조해 중복을 피하고, `pxPrice`에 행사 전 PX 판매가만 입력합니다. 불명확한 PX가는 비워 둡니다.
5. 공식 상품 사진·상품 링크·포장 차이를 기록하고 `node build.mjs`로 빌드한 뒤 링크와 가격을 검토해 게시합니다.

2026년 10월은 할인표 사진 3장과 텍스트 요약 3장을 대조한 47개 품목·규격 기록입니다. 사진과 텍스트가 충돌하는 에버콜라겐 용량·관절살리도 수량·카라반팔 100 사이즈 가격은 사진을 우선합니다. 가격 동일 2개, 가격 상승 1개도 표에 그대로 보관하며 할인으로 표시하지 않습니다. 사진이 잘린 95 사이즈 행사가와 바로핫팩 가격은 텍스트 요약을 기준으로 기록했습니다.

## 새 글 발행

`content/editorial.json`에 고유한 `slug`, `title`, `summary`, `image`, `sections`를 추가합니다. 초기 9개 글의 추가 원고는 `content/expanded.json`에 있습니다. 보조 30개 가이드의 주제별 판단 문장은 `content/guide-notes.json`, 핵심 5개 글의 직접 답변·출처·적용 범위는 `content/guide-facts.json`에서 관리합니다. `sections`는 `[제목, 본문]` 배열입니다. 글자 수로 품질을 판단하지 않습니다. 질문에 대한 답, 독자적 예시, 주장과 연결되는 근거, 적용 범위를 사람이 점검한 뒤 게시합니다. 상품의 현재 가격·재고·효능은 확인하지 않았다면 단정하지 않습니다. 외부 이미지는 사용 허가를 별도로 확인합니다. `node build.mjs`를 실행하면 글 목록과 개별 URL이 함께 갱신됩니다.

실제로 원고를 고쳤을 때만 `modifiedAt`을 `YYYY-MM-DD`로 설정합니다. `publishedAt`과 외부 자료의 `reviewedAt`은 기록을 확인한 경우에만 별도로 기입하고 화면·구조화 데이터와 일치시키세요. 확인 이력이 없으면 날짜를 추정하지 않습니다. 사이트맵의 `lastmod`는 실제 수정일이 기록된 글에만 나옵니다.

## GEO 검수

- [보완 계획서](GEO_PLAN.md)에 적힌 핵심 5개 글의 답변·출처·적용 범위와 보조 30개 글의 고유성을 편집자가 검토합니다.
- 공개 후 Search Console에서 대표 URL의 색인·스니펫을 확인하고 사이트맵을 제출합니다. 현재 사이트 소유자 계정 연동 결과는 원본 저장소에서 확인할 수 없습니다.
- 실제 사용자 질문과 AI 답변의 링크·오인용은 날짜와 질의 환경을 함께 기록합니다. 검색 노출과 AI 인용은 보장되지 않습니다.

## 공식 제품 이미지 추가

`content/product-images.json`에서 글의 `slug` 아래에 제품별 객체를 추가합니다. 필수 값은 `name`, `brand`, `imageUrl`, `productUrl`, `note`입니다. 공식 제조사·브랜드의 정확한 상품 페이지에서 제품명과 이미지를 대조하고, 그 페이지에서 제공하는 이미지 주소만 `imageUrl`에 넣습니다. 두 URL은 HTTPS여야 합니다. 이미지는 원본 주소에서 직접 표시하며 이 사이트에 복제하지 않습니다. 페이지에 공식 상품 링크와 이미지 설명이 함께 표시됩니다. 공식 사이트에 올라온 이미지라도 재사용 허가가 자동으로 주어지는 것은 아닙니다. 광고를 게재하거나 심사를 신청하기 전에는 이미지 사용 권한을 확인하고, 허가받지 못한 이미지는 제거하거나 직접 제작한 이미지로 바꾸세요. PX 재고나 판매 여부가 확인되지 않았다면 `note`에서 그 사실을 명시합니다.

## 애드센스 시작 전

- 공개할 운영자명과 개인정보 처리 기준을 확정해 소개·개인정보 안내에 반영합니다. 문의 이메일은 `honglabai@gmail.com`으로 설정했습니다.
- 사이트는 공개 상태입니다. 심사 신청 전에 외부 브라우저에서 전체 페이지와 이미지 접근을 다시 확인합니다.
- AdSense 계정의 실제 게시자 ID를 받아 사이트 연결 방식과 ads.txt를 설정합니다. 가짜 ID를 넣지 않습니다.
- 광고 및 쿠키 처리를 시작하기 전에 개인정보 안내와 필요한 지역별 동의 설정을 실제 동작에 맞게 갱신합니다.
- 사이트의 내용, 사실, 출처 및 이미지별 사용 허가 범위를 사람이 검토한 뒤 AdSense 심사를 요청합니다. 승인 여부는 Google이 결정합니다.

## 공통 화면 규칙

모든 메뉴의 최종 스타일은 `content/design-system.css`에서 관리합니다. 이 파일은 이전 스타일 다음에 적용됩니다. 제목 28px(모바일 24px), 섹션 제목 20px, 카드 제목 16px, 본문 16px, 보조 글 14px를 공통 변수로 사용합니다. 상단 제목·설명·구분선과 콘텐츠 시작 여백을 일치시키고 700px 이하 상품 목록은 두 열, 중간 화면은 네 열, 넓은 화면은 다섯 열로 배치합니다. 홈 카드 제목은 움직이지 않고 자연스럽게 줄바꿈합니다.

## 가격 비교 중심 목록
홈, 월별 할인, 제품 소개, 구매 가이드의 상품 목록은 상품명·사진·두 가격·확인된 가격 차이를 우선 표시한다. 목록 설명은 제품 상세에 두고 월별 행사 조건·출처·보존된 월별 기록도 해당 상세에서 확인할 수 있다. 카드 간격은 8px이며 모바일은 2열, 데스크톱은 5열이다. 아이스크림 상품 사진은 실제 포장 사진을 사용하고 상세에 사진 출처와 묶음 구성 차이를 명시한다. 원래 첨부표는 PX가 근거로 유지한다.

사진이 없는 상품이나 로드에 실패한 상품에는 500×500 원본의 `assets/home/image-pending.svg`를 사용한다. “이미지 확인 중”이라고 표기하고 실제 상품 사진과 동일한 카드 프레임 크기를 적용한다. 제품명에서 “(영외)”는 표시하지 않으며 판매 조건 관련 원자료는 보존한다.

홈은 햄버거 메뉴를 표시하지 않으며 높이 약20svh인3개 배너를2초마다 왼쪽으로 전환한다. 조작 버튼 없이 2초 간격으로 3개 배너가 순환하며 클릭하면 해당 메뉴로 이동한다. 동일 브랜드의 다른 제품 사진은 참고 이미지로 명시하고 원래 상품 가격과 규격은 유지한다.

주요 메뉴는 선택된 탭과 본문이 연결되는 파일철 형태로 표시한다. 월별 할인은 할인가, 제품 소개는 PX가로 가격순 정렬한다. 등록순은 기존 등록 순서이며 할인율순은 높은 순이다. 판매량순은 집계 데이터가 없으므로 할인율순과 같은 결과를 표시한다. 미확인 가격·할인율은 뒤로 보내며 검색·품목 필터·10개 페이지 표시와 함께 작동한다.

## 상품 이미지 최적화
`python scripts/download-product-images.py`로 저장된 공개 원본을 확보합니다. 선택적으로 한 번에 처리할 최대 개수를 인자로 지정할 수 있습니다. 실패한 다운로드는 기존 이미지를 유지합니다. 추가 확보한 원본은 `content/product-image-sources-extra.json`에 기록합니다.

`python scripts/optimize-product-images.py`는 원본을 확대하지 않고 카드용 최대 320px, 상세용 최대 960px WebP를 생성하며, 결과와 실제 크기를 `content/product-image-manifest.json`에 기록합니다. 상품의 지정된 사진 영역과 이미지 외부의 흰 여백을 먼저 정리하고 EXIF는 배포본에 포함하지 않습니다. 이후 `node build.mjs`를 실행합니다. 원본은 배포하지 않고 내용 해시가 붙은 최적화 이미지만 사이트에서 사용하며, 화면 크기에 따른 선택·지연 로딩·이미지 캐시를 적용합니다.
